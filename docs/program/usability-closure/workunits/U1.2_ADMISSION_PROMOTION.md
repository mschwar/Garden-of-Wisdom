# U1.2 — Minimum admission metadata + T-P2 canonical promotion

## Primary lane

Human curation. Secondary: Platform/governance.

## Why this exists

After U1.1 rules the authority model, an `eligible` candidate needs one explicit human admission step and enough Garden-facing metadata to participate in the existing product surface.

## Inputs / dependencies

Operator-approved U1.1 decision; STATE_MODEL T-P2 and reversal invariants; store schema; candidate/review surfaces; admission metadata spec.

## In scope

- Persist the minimum admission metadata ruled by U1.1, and nothing broader.
- Implement an operator-facing explicit admission command/surface.
- Implement/audit T-P2 `eligible → canonical` with operator authority.
- Enforce prerequisites: curation accepted; required Garden display metadata present; uncertainty visible.
- Do **not** require `research_state=verified`; `not_started` remains legal and must project later as unverified.
- Handle or safely block canonical curation reversals so no illegal stranded state is possible. If the approved design requires retirement/reversal transitions now, implement exactly the minimum necessary set with audit.
- Add acceptance and negative controls.

## Out of scope

Projection generator, browser switch, W2 research, broad enrichment, ontology cleanup.

## Human gates

Every canonical admission is explicit operator authority. Test fixtures may simulate operator authority; production command may never auto-admit.

## Acceptance criteria

- non-eligible candidate cannot admit;
- missing required admission metadata cannot admit;
- eligible accepted candidate with metadata can admit;
- T-P2 audit row records actor/time/from/to/reason;
- research state unchanged;
- no path produces canonical + rejected/hold/duplicate stranded state;
- refused action writes nothing.

## Evidence required

Happy path, every refusal, canonical reversal consistency, negative control showing auto-admission/verification would fail.

## Stop condition

Store can hold a properly admitted new canonical item. It is not yet part of browser/read model. Next U1.3.

## Builder prompt

Implement U1.2 strictly under the operator-approved U1.1 architecture.

Add only the minimum metadata and explicit operator T-P2 admission path required to make a candidate canonical. Do not build projection/browser/research.

Preserve the critical invariant: canonical does not mean verified. Prove research state does not change.

Also prove canonical items cannot become stranded when curation reverses: implement the approved minimum reversal/retirement behavior or refuse unsafe transitions explicitly.

Open one PR with `GARDEN_U1_2_HANDOFF.md`, acceptance + negative controls, then stop for QA.

## Foreign QA prompt

Try to force:
- auto-admission without operator action;
- admission from wrong curation/corpus state;
- admission with missing metadata;
- research-state upgrade as a side effect;
- canonical + rejected/hold/duplicate inconsistent state;
- partial audit/state write.

PASS only if every refusal is write-free and every successful admission is auditable and uncertainty-preserving.
