# U0.1 — Store lifecycle + mirror freshness invariant

## Primary lane

Platform/governance. Secondary: ingestion/normalization.

## Why this exists

The SQLite database is machine-local while `data/store/garden.export.txt` is the committed diffable mirror. Today hydration/export are separate operations. A real mutation can therefore exist only on one machine or leave the committed mirror stale if the operator forgets a ritual.

Gate U0 cannot pass while persistence depends on memory.

## In scope

Implement a small, obvious store lifecycle primitive that makes these operations safe:

1. **Bootstrap/hydrate**: if local SQLite is absent and a committed mirror exists, reconstruct the local store from that mirror.
2. **Status/freshness**: compare the live local store's deterministic export with the committed mirror and report `CURRENT`, `STALE`, `MISSING_DB`, or `MISSING_MIRROR` (names may vary, semantics may not).
3. **Sync/export**: atomically refresh the committed mirror from the local store.
4. **Mutation invariant**: no successful operator-facing mutating command may exit 0 while the committed mirror is silently different from the resulting store. Choose the smallest coherent mechanism and prove crash/failure behavior is recoverable.
5. **Divergence safety**: bootstrap must never silently overwrite a non-empty/divergent local store with the mirror or vice versa.
6. Add deterministic acceptance/negative controls.
7. Document one obvious operator path in RUNBOOK.

## Out of scope

## Human gates

None if the implementation preserves the already-ruled SQLite + deterministic-mirror architecture. If the agent concludes that architecture must change, STOP and escalate instead of changing it.

## Acceptance criteria

From a temp clean-clone-shaped directory:

- mirror exists, SQLite absent → bootstrap recreates store and exported bytes equal mirror;
- both absent → behavior is explicit, not guessed;
- SQLite and mirror equal → status says current;
- mutate through a real operator surface → successful command leaves status current, or the command fails loudly before claiming success;
- manually alter/withhold mirror → status detects stale;
- divergent local DB + mirror → bootstrap refuses destructive guess;
- delete local SQLite → re-bootstrap → export byte-identical;
- D3/D4 committed state survives round-trip;
- existing W1 suites remain green.

## Evidence required

Transcript of all lifecycle states, exact before/after hashes, one injected-failure control, one stale-mirror control, full relevant acceptance run.
