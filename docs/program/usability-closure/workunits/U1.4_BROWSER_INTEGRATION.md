# U1.4 — Browser consumes the unified Garden read model

## Primary lane

Platform/governance. Secondary: product surface.

## Why this exists

Until the actual browser shows newly admitted items, the growth skeleton still does not reach the product.

## Inputs / dependencies

U1.3 projection; `browser/`; `smoke_quote_browser.py`; Pages workflow/contract; live acceptance checker.

## In scope

- Switch browser data loading to the approved unified read model.
- Preserve existing search/filter/sort/copy/empty-state behavior.
- Ensure uncertainty/verification for new canonical items is visible.
- Update smoke and Pages contract to validate the new artifact path.
- Ensure existing 324 rows remain visible and behaviorally stable.
- Ensure generated/read-model files are what Pages serves and live checker verifies.
- Keep browser read-only.

## Out of scope

Writable browser, research UI, capture UI, broad UX redesign.

## Acceptance criteria

With at least one canonical store fixture/item:
- browser total = unified projection count;
- new item findable by text search;
- its unverified/uncertain status visible;
- all six filters/sort/copy still work;
- zero failed data requests;
- Pages contract tests the new data path;
- old legacy corpus does not silently disappear or duplicate;
- mobile smoke remains green.

## Evidence required

Headless Chromium transcript, exact counts derived from projection, local/live path checks, negative control repointing browser to stale legacy-only CSV and proving smoke fails.

## Stop condition

Browser is connected to unified read model. Next U1.5 persistent gate proof.

## Builder prompt

Execute U1.4 as an integration unit, not a redesign.

Point the real browser at U1.3's derived read model and update every contract/smoke/live check that currently assumes root legacy CSVs are the browser's direct data source.

Preserve all existing browser behavior. Add a negative control proving the smoke goes red if the browser is accidentally repointed to the legacy-only 324-row source while a new canonical item exists.

Open one PR + handoff, stop for QA.

## Foreign QA prompt

Drive the real browser in Chromium against the PR.

Verify the new canonical item is actually found and visibly unverified. Confirm all legacy counts/filter/sort/copy semantics remain correct.

Intentionally simulate legacy-only data or a missing generated artifact and verify tests fail loudly. Check Pages artifact/path rules still prevent silent zero-row/stale-data deploys.
