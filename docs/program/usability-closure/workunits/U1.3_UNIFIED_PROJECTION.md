# U1.3 — Deterministic unified Garden read model

## Primary lane

Platform/governance. Secondary: Enrichment/classification only to the minimum already ruled.

## Why this exists

The browser needs one coherent Garden-facing dataset combining preserved legacy canonical rows and newly canonical store items without turning the projection into another write authority.

## Inputs / dependencies

U1.1 architecture; U1.2 canonical store item; legacy CSV contracts; current validator/browser schema.

## In scope

Build a deterministic projection generator that:
- reads authoritative legacy inputs + canonical store state;
- emits the exact versioned unified read model ruled by U1.1;
- contains all legacy canonical rows plus admissible new canonical store items;
- gives stable deterministic IDs/identity according to the ruling;
- maps research state to visible verification status without overstating certainty;
- maps source fields exactly as ruled;
- excludes non-canonical candidates;
- is reproducible byte-for-byte from authoritative inputs;
- includes content identity/digest or equivalent immutable build identity if U1.1 requires it;
- validates itself;
- cannot be edited to mutate source authority.

## Out of scope

Browser changes, W2 research, general source enrichment.

## Acceptance criteria

Using a fixture/persisted store with one new canonical candidate:
- projection row count = legacy count + admitted items;
- all legacy rows preserve their observable values;
- noncanonical candidates absent;
- canonical `research_state=not_started` is visibly unverified;
- repeated generation byte-identical;
- delete generated files and regenerate → identical;
- mutate generated file only → regeneration/validator catches/replaces it; no upstream state changes.

## Evidence required

Hashes, row-level before/after comparison over all legacy rows, generated-row example, negative control.

## Stop condition

Unified read model exists and is deterministic. Browser still uses old source until U1.4.

## Builder prompt

Implement U1.3 from the approved architecture.

Treat the read model as a build artifact, never a write API. Prove every legacy row's observable product data is preserved and only canonical store items are added.

Generate twice, delete/regenerate, hash, validate, and compare every legacy row. Add a control showing hand-editing the projection cannot mutate authority.

Do not change browser fetches yet.

Open one PR + `GARDEN_U1_3_HANDOFF.md`; stop for QA.

## Foreign QA prompt

Independently rebuild the projection from authoritative inputs.

Compare all legacy rows, not a sample. Try to leak an eligible-but-not-canonical candidate into the output. Try a canonical unverified item and confirm it is not displayed as verified. Hand-edit the projection and verify rebuild restores authoritative output.

Check stable ID/source behavior matches U1.1 exactly.
