## Caveat on near-duplicate detection

The validator flags a pair as a near-duplicate candidate if they share an exact `source_ref` OR
have >0.6 text similarity. This is **noisy for generic source_ref labels**: many oral-tradition
rows share the literal `source_ref` value `"Oral Tradition"` with no further pinpoint citation,
so they get flagged against each other even when the quotes are unrelated (e.g. #319 "We are
the ones we've been waiting for" vs #331 "One finger cannot lift a pebble" — both `Oral
Tradition`, nothing else in common). Roughly half the 45 flagged pairs are this false-positive
pattern. The other half — same specific citation (`Gita 2.47`, `Yasna 43:1`, several
`Dhammapada` verses, several Bahá'í `Gleanings` sections) — are more likely genuine variant
translations of the same verse and worth a human look.

> **Exact counts (2026-09-13, issue #31).** "Roughly half" re-derives to **30 of 45** pairs sharing
> a citation that pinpoints nothing (**25** of them the bare `Oral Tradition` label) against **15** that
> warrant a human look (**13** plus a pinpoint locator, **2** text-similarity-only). The full breakdown
> and its classification rule are in "Re-derivation 2026-09-13" at the end of this file.

## Re-derivation 2026-09-13 (issue #31)

The near-duplicate heuristic used to score each pair with ONE directional
`difflib.SequenceMatcher.ratio()` call. That ratio is **not symmetric**, so the number a pair was
reported with was a function of the order the two rows happened to be visited in, not of the pair.
Two measured consequences on this corpus:

- pair `113 ~ 114` scored `0.69` one way and `0.67` the other, so the 2026-09-11 transcript above
  cannot be reproduced in the other order;
- pair `189 ~ 216` straddles the `0.60` threshold (`0.6023` one way, `0.5909` the other), so a
  re-run in the other order can **appear or disappear**, not merely shift.

The scorer now returns the **mean of both directional ratios** (the same rule W1.4's store-side hint
generator adopted, `docs/program/W1_4_NORMALIZATION_HINTS.md` §3 ruling 1), and the validator
**hard-fails** if a second detection pass over the same rows with every tradition reversed disagrees
with the first -- so an order-dependent number is a `RESULT: FAIL`, not a curation item. A second hard
check re-derives each printed reason from the rows themselves, so a citation pair that also clears the
text threshold must carry its number (three pairs do today).

### The two related questions #31 asked to decide

**1. Should a shared citation also report text similarity? Yes** -- the two kinds of evidence are
independent, and a pair that shares a pinpoint citation *and* reads nearly identically is stronger than
either alone. Three pairs qualify today (`66 ~ 67` 0.60, `201 ~ 306` 0.86, `209 ~ 301` 0.82). They are
annotated rather than added, so the pair count does not move. A hard check enforces the annotation.

**2. Should the comparison stay scoped within one `tradition`? Yes, for now -- and the measurement is the
reason.** A corpus-wide sweep flags **196** pairs instead of 45: **146** of the 151 additions share a
`source_ref` across traditions (the same bare `Oral Tradition` label matching unrelated rows), so
widening it now would bury the signal. It is not a pure loss: **5** cross-tradition pairs are
text-similarity driven, and at least one is a real overlap -- `39` (Christianity, 'Thou shalt love thy neighbour as thyself.') ~ `53` (Judaism, 'Love thy neighbour as thyself.') at 0.82. That
is a curation-policy change to a frozen artifact, so it is filed as its own spec
([#34](https://github.com/mschwar/Garden-of-Wisdom/issues/34)) rather than
taken here. **The 45-pair count is the tripwire**: a change to this scope moves it, and the transcript
records it.
